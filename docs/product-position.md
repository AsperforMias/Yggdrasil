Yggdrasil， 这是我的一个梦想，也是一个尝试性的练手项目

它主要训练的是后端系统设计与模拟服务器能力，不是传统 CRUD 后端，也不是狭义 agent 开发

更准确地说，它像是：

> **面向多 agent 接入的权威世界模拟后端 / 类游戏服务器 / 事件驱动状态裁决系统**

agent 在这里更像“外部用户”或“客户端”。它们提供压力、意图和不确定性，但项目真正的核心能力在 Yggdrasil 这一侧：世界如何保持权威、并发下如何裁决、状态如何一致、事件如何回放、规则如何扩展

我主要希望在这个过程中，它也能训练我这些能力：

- **事件驱动能力**：用事件日志、快照、MQ、worker pool 支撑异步处理和可回放
- **服务端架构能力**：REST API、gRPC、限流、超时、重试、熔断、缓存、消息队列
- **并发裁决能力**：多个 agent 同时提交动作时，如何排序、校验、冲突解决
- **事务与一致性能力**：交易、资源消耗、奖励、背包变更如何避免半成功状态

- **状态建模能力**：世界、实体、位置、资源、关系、任务、事件、观察视图怎么抽象
- **规则引擎思维**：不是写一堆接口，而是让世界规则可以被组合、测试、演化
- **模拟系统思维**：时间推进、tick、行为队列、观察范围、局部世界状态

所以它不是普通的“传统 server 后端”，因为普通后端常见的是请求进来直接查库改库。而你的项目更难：请求只是意图，真正的修改要经过世界规则裁决

它也不是典型“agent 开发”，因为 agent 开发重点通常是 prompt、memory、planning、tool use、RAG、reflection、evaluation。而这里的重点不是让 agent 更聪明，而是让**世界足够稳定、权威、可承载很多聪明或不聪明的 agent**

可以这样定位它：

> 一个使用 Go 构建的多智能体接入型权威世界模拟服务器，核心关注并发状态裁决、事件驱动架构、事务一致性、服务治理和可回放世界状态

如果后续需要再单独写一个 agent-runner 来负责记忆、反思、计划、调用模型，那才是 agent 开发部分。Yggdrasil 本体更应该被称为是...“世界内核”？
